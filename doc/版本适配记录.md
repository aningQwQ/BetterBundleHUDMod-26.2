# 版本适配记录

记录各目标版本与 `main` 的差距，`main` 

基线为 Minecraft 26.2、mod 1.8.0。

## 目标 26.1 / 26.1.1 / 26.1.2

相对 `main`（26.2）只有两处差距。一是屏幕访问，26.1.x 要用 `client.screen`，不能用 `client.gui.screen()`，涉及 gui 与 mixin 下的几处调用。二是依赖，整套换成 26.1.x 的构件：MC 26.1.2、Fabric API 0.155.3+26.1.2、Cloth Config 26.1.154、ModMenu 18.0.2、loader 0.19.5，`fabric.mod.json` 的 `depends.minecraft` 相应改为 `>=26.1 <26.2` 等。Gradle/Loom 不动，输入与 Bundle API 也不用改。

## 目标 26.3

相对 `main`（26.2）差距如下。输入相关从直接调 GLFW 改为用 `InputConstants`（含键码常量，搜索框那几个裸键码一并替换）。Bundle 内容 API 由 `itemCopyStream()` 改名为 `itemCopies()`，`gui`、`sort`、`util` 下几处调用要跟着改。依赖整套换成 26.3 的构件：MC 26.3、Fabric API 0.162.0+26.3、Cloth Config 26.3.159、ModMenu 21.0.0、loader 0.19.5，`depends.minecraft` 改为 `>=26.3`。另外 Gradle 升到 9.8.1、Loom 升到 1.18.4。屏幕访问不用动。

## 目标 1.21.9 / 1.21.10 / 1.21.11（2026-10）

从 `main` 派生独立分支 `1.21.9`，输入事件 API 与 26.x 同代，因此不再保留 1.21.x 的旧输入条件分支。

### 构建工具链
- Stonecutter 0.9.8 + loom-back-compat 0.4.3，Loom 1.17.21，Gradle 9.5.1，JDK 21
- 版本登记在 `settings.gradle`，1.21.9 为基线和 `vcsVersion`
- 版本差异集中在 `versions/<版本>/gradle.properties`

### 相对 main 的回退
- 渲染：`GuiGraphicsExtractor` → `GuiGraphics`；`item/text/itemDecorations` → `renderItem/drawString/renderItemDecorations`
- 注入点：`extractContents` → `renderContents`
- 配置：`AutoConfigClient` → `AutoConfig.getConfigScreen`
- Bundle：`Fraction.result()` → `weight()`
- 网络：`ContainerInput` → `ClickType`
- 屏幕访问：`client.gui.screen()` → `client.screen`
- 输入保持 `MouseButtonEvent` / `KeyEvent` / `CharacterEvent`，与 1.21.9+ 一致

### 依赖
- 1.21.9：Fabric API `0.134.1+1.21.9`、Cloth `20.0.149`、ModMenu `16.0.1`
- 1.21.10：Fabric API `0.138.4+1.21.10`、Cloth `20.0.149`、ModMenu `16.0.1`
- 1.21.11：Fabric API `0.141.6+1.21.11`、Cloth `21.11.160`、ModMenu `17.0.1`
- 1.21.10 / 1.21.11 源码无需额外改动

### 验证
- `./gradlew build --no-parallel` 三个版本全部通过
- 三个实例均使用 Fabric Loader 0.20.0，测试通过
